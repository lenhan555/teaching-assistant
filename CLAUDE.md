# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

---

## Project Mission

This is an **intelligent agent-based teaching assistant system** for an Excel, SQL, and Power BI training center. It operates as a squad of specialized agents that collaborate autonomously to:

1. **Research** training topics across trusted sources
2. **Synthesize** findings into structured knowledge documents
3. **Generate** polished slide deck blueprints with in-class exercises and take-home assignments
4. **Grade** submitted homework against rubrics and produce feedback
5. **Feed insights** from each cohort back into better materials for the next — a continuous improvement loop

Instructors use this system to offload content preparation and grading, freeing them for mentorship and live troubleshooting.

## Folder Architecture

```
Teaching Assistant/
├── .claude/
│   ├── agents/                      # Native Claude Code sub-agents (isolated workers)
│   └── commands/                    # Registered slash commands (one per skill)
├── skills/                          # Reusable slash-command skills (invoked via /skill-name)
├── workflows/                       # Multi-step orchestration pipelines
├── submissions/                     # Instructor drops student files here (create per cohort)
├── assignments/                     # Lesson assignment markdown files (input for grading)
├── rubrics/                         # Grading rubrics generated by rubric-builder
├── grades/                          # Per-student feedback files output by grading-agent
├── log/                             # Append-only activity logs written by agents and workflows
├── hooks/                           # Event-triggered automation
├── tools/                           # Python conversion scripts (SVG → PPTX, blueprint → HTML)
├── slide_deck_template/
│   ├── examples/deck-analysis.md   # Full visual design system reference for PPT
│   └── decks/[subject]/             # Generated slide blueprints, grouped by subject

```

**Skills vs Agents vs Workflows:**
- **Skills** (`skills/*/SKILL.md`) — invoked interactively by the instructor via `/skill-name`
- **Agents** — two kinds (see below)
- **Workflows** (`workflows/*.md`) — orchestration layer sequencing multiple agents through a full pipeline

## Two Kinds of Agents

### Native Claude Code Sub-Agents (`.claude/agents/*.md`)
These are real isolated workers registered with Claude Code. Each has YAML frontmatter specifying `name`, `description`, `model`, and `tools`. Claude Code can spawn them as separate processes with restricted tool access, enabling true parallelism and model-level cost control. These are the **active** agents the system uses.

Model tiering:
- **Haiku** (`claude-haiku-4-5-20251001`) — mechanical extraction tasks: `excel-scanner`, `rubric-builder`
- **Sonnet** (`claude-sonnet-4-6`) — judgment and writing tasks: all others

## Active Skills

### `/sql-knowledge-research-update [level] [topic] [--update]`
Researches SQL concepts at `beginner`, `intermediate`, `advanced`, or `all` levels. Produces a structured report with concepts, worked examples, exercises, and a quick-reference table. With `--update`, merges into `skills/sql-[level]-[topic].md`.

### `/slide-deck "<topic>" [--slides N] [--audience <audience>] [--style <style>] [--save]`
Generates a complete slide-by-slide PPT blueprint. Reads the design system from `slide_deck_template/examples/deck-analysis.md` and `slide_deck_template/examples/svg-design-system.md`. After PPTX export, automatically runs the `slide-qc` agent to validate against both design references. Supports three styles: `pitch`, `training`, `report`. Saves to `slide_deck_template/decks/[subject]/[topic-slug].md`.

### `/excel-knowledge-research-update [level] [topic] [--update]`
Same pattern as the SQL researcher, but for Excel topics (formulas, PivotTables, Power Query).

### `/power-bi-knowledge-research-update [level] [topic] [--update]`
Research DAX, data modeling, and report design by level.

### `/assignment-generator`
Produces take-home assignments from a topic and difficulty level.

### `/rubric-builder`
Generates grading rubrics from an assignment file. Output: `rubrics/[subject]-[level]-[topic-slug]-rubric.md`.

## Active Workflows

### `workflows/grading-run.md`
Grades text/markdown student submissions. Sequence: rubric lookup → Grading Agent (per student) → Cohort Feedback Agent.

### `workflows/excel-grading-phase.md`
Trigger: `/grade-excel-cohort <subject> <level> <cohort_id> <submissions_dir>`

Grades Excel homework (`.xlsx` workbooks). Sequence per student:
1. **Excel Scanner** — extracts sheet contents via `openpyxl` → `agents/excel-scanner/output/[student-id]-scan.md`
2. **Excel Reconciler** — matches each sheet to a lesson assignment; judges task completion (✅/⚠️/❌) → `agents/excel-reconciler/output/[student-id]-reconciliation.md`
3. **Grading Agent** — maps reconciliation statuses to rubric marks → `grades/[subject]-[level]-[cohort-id]-[student-id]-feedback.md`

After all students: **Cohort Feedback Agent** → `log/cohort-[cohort-id]-[subject]-[level]-feedback.md`

### `workflows/full-course-prep.md`
End-to-end content preparation pipeline: research → synthesize → slide generation → assignment + rubric creation.

## Excel Grading — Key Conventions

- **Student ID** is derived from the `.xlsx` filename: strip extension, lowercase, spaces → hyphens
- **Assignment matching** is convention-based (no manifest): sheet name is normalized to keywords, then scored against filenames in `assignments/` filtered by subject and level. Filenames must include subject and level to be matched.
- **Reconciliation statuses:** ✅ Complete (full marks), ⚠️ Partial (partial marks if rubric allows), ❌ Missing (zero)
- **`openpyxl`** must be installed: `pip3 install openpyxl`. Excel Scanner aborts if not available.

## Design System

Two design reference files live in `slide_deck_template/examples/`:

| File | Purpose |
|------|---------|
| `deck-analysis.md` | Visual design analysis of the original pitch deck template — brand, color rationale, layout patterns with ASCII diagrams, PPT replication notes |
| `svg-design-system.md` | **Authoritative SVG spec** — all rules for canvas, color tokens, typography, layouts A–G, divider/slide-number snippets, and SVG non-negotiables. Read this before writing any SVG. |

Any slide-related skill or agent must apply:

- **Two-tone headline:** one neutral word (near-black) + one accent word (green-mid). Color only — never mix fonts.
- **Background alternation:** dark-green and white slides alternate; never more than 2 consecutive same-mode slides.
- **1 concept per slide:** title is the conclusion; content is the evidence.
- **Color tokens:** `green-dark #1A6B3A`, `green-mid #2EAA5E`, `green-light #5CDB8F`, `white`, `near-black #1A1A2E`, `grey-body #4A4A6A`
- **Font:** Poppins (fallback: DM Sans, Inter)
- **Layout patterns A–G** are defined in `svg-design-system.md` and must be selected by name

## Agent Logging

All agents and workflows append to `log/` when they run. Logs are append-only — never overwrite.

**File naming:** `log/<agent-or-skill-name>.log`

**Log entry format:**
```
[YYYY-MM-DD HH:MM] <agent-or-skill-name>
  Input:   <topic, level, or task description>
  Output:  <files written or action taken>
  Status:  success | partial | failed
  Notes:   <optional — errors, skipped steps, or notable findings>
```

## Conventions for Adding New Skills

1. Create `skills/<skill-name>/SKILL.md`
2. Structure: Usage block → Arguments → Examples → numbered Execution Steps
3. Steps must be self-contained — the executing model has no prior context
4. Skills that write files must define: output path, file naming convention, and merge/overwrite rules
5. Skills that do web research must list explicit search query templates and preferred sources
6. To make a skill callable as `/<skill-name>`, copy or symlink `skills/<skill-name>/` into `.claude/skills/<skill-name>/`

## Conventions for Adding New Agents

1. Create the native sub-agent at `.claude/agents/<name>.md` with YAML frontmatter: `name`, `description`, `model`, `tools`
2. Mirror it as human-readable spec at `agents/<name>/AGENT.md`
3. Each agent has a single responsibility — no grading in the scanner, no scanning in the grader
4. Specify exactly the tools the agent needs and no more
5. Every agent must log to `log/<agent-name>.log` as its final step
6. Every agent must output a `output_path:` line as its final output for workflow handoff

## Conventions for Adding New Workflows

1. Add to `workflows/`
2. Document: trigger command, agent sequence with data flow, output paths, error handling (skip-and-continue vs abort)
3. Workflows must handle partial failures — one student failing should never abort the whole cohort run
